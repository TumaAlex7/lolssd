# Режим «Linux (QEMU windows)» — не работает

Ветка хранит второй режим вывода ВМ: экраны в окнах самого QEMU вместо VNC и TigerVNC
(`lolssd-win desktop-qemu`). В `main` его нет: на Windows он не заработал.

- **SDL** (`-display sdl`): QEMU виснет вместе с гостем, как только окно видно. Причина —
  взаимная блокировка в QEMU 11.1 (`ui/sdl2.c`), снята дампом процесса на ноутбуке автора:
  гость включает USB-планшет, поток процессора гостя (с общей блокировкой QEMU) вызывает
  `sdl_mouse_mode_change`, тот захватывает мышь и меняет заголовок окна (`SDL_SetWindowTitle` →
  `SetWindowTextW`). На Windows это синхронный `SendMessage` потоку окна (`main`), а он ждёт ту же
  блокировку. Исправление — `sdl2-mouse-mode-deadlock.patch` (работа уходит в главный цикл), но
  для него нужна своя сборка QEMU для Windows.
- **GTK** (`-display gtk`): работает, но все выходы в одном окне (остальные — вкладки), то есть
  Linux виден только на одном мониторе.
