# lolssd

League of Legends на внешнем SSD для компьютера с Linux.

Внешний SSD с урезанной Windows и лолкой: подключил, загрузился с него, играешь. Порядок
загрузки компьютера не меняется: следующая загрузка, как обычно, идёт в Linux. По желанию твой
Linux продолжает работать внутри этой Windows — в виртуальной машине, со своего же диска, своим
ядром, на весь экран каждого монитора.

Заранее в Linux ничего ставить не нужно: всё, что требуется от системы, делает утилита `lolssd`,
лежащая на самом SSD.

> **Версия 0.1. Проверено только на ноутбуке автора** (AMD, Arch Linux, Hyprland). На другом
> железе может не заработать, ничего не обещаю.

## Почему так

Vanguard (античит Riot) работает на уровне ядра Windows и не запускается ни через Wine/Proton,
ни в виртуальной машине, ни в облачном гейминге. Остаётся настоящая Windows на настоящем
железе. Этот проект делает её отдельным внешним диском, который не трогает систему хоста:
что именно он гарантирует хосту — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), §2.

## Что нужно

- компьютер с UEFI, TPM 2.0 и включённой виртуализацией (`lolssd check` проверит);
- от 120 ГБ под Windows: внешний SSD (лучше NVMe в корпусе USB 10 Гбит/с с UASP), свободное
  место на диске или целый диск;
- стоковый ISO Windows 11 с сайта Microsoft;
- для установки: QEMU, OVMF и swtpm — если их нет, мастер поставит их сам на время установки и
  удалит после, как yay сборочные зависимости (pacman, apt, dnf, zypper); интернет;
- для Linux внутри Windows — система хоста с `mkinitcpio` (как Arch).

## Установка

```
./lolssd-setup            # готовый бинарник из релиза; из исходников — build/lolssd-setup (нужен Go)
```

Мастер в терминале, по шагам:
1. **ISO Windows 11** — стоковый, находит в `~/Downloads` сам. Образ не переделывается.
2. **На какой диск.** Есть на нём свободное место от 120 ГБ (например, рядом с Linux на
   внутреннем диске) — Windows встаёт туда, остальное не трогается; нет — диск стирается
   целиком (если он не занят). Разделы мастер не ужимает: место освобождается заранее. Внешний USB-диск — Windows, переезжающая между компьютерами; внутренний — обычная
   Windows этого компьютера.
3. **Что ставить**, галочками: Windows Update (по умолчанию выключен: с ним вместе с драйверами
   приходят программы производителя, а нужных драйверов он часто не приносит), Linux внутри Windows,
   предустановка League of Legends, удаление Edge (браузер, его или любой другой, ставится из
   Microsoft Store), OneDrive и лишнего (раскрывается списком), Sunshine для стриминга, локальный
   пользователь `lol` без пароля. Обои K/DA — всегда.
4. **Драйверы** именно этого компьютера (Wi-Fi, звук, чипсет): папки с `.inf` Windows ставит
   сама, установщики `.exe`/`.msi` окажутся в папке `Drivers` на рабочем столе. Драйвер видеокарты
   отдельно не нужен: установщики AMD Software, NVIDIA App и Intel DSA Windows скачивает при
   установке, и для карты без драйвера нужный запускается сам при входе (и обновляет себя).
5. Сводка → `sudo install.sh`: раздел `LOLSSD` в начале свободного места (только он) и установка
   в окне QEMU. Установщик Windows спросит язык, редакцию (ту, что была на компьютере, —
   активация по цифровой лицензии), ключ («У меня нет ключа») и где установить: «Незанятое
   место» — ESP, MSR и C: он создаст сам. ВМ видит только выбранный диск. Дальше без вопросов: перезагрузки, скачивание компонентов (QEMU и
   TAP для Linux внутри Windows, TigerVNC, Sunshine, установщики видеодрайверов — с проверкой
   контрольных сумм), первый вход, установка Riot — дождаться, пока клиент предложит играть, и
   выключить Windows.

Рядом с Linux на том же диске на время установки размонтируется ESP, а запасной загрузчик
`\EFI\BOOT\BOOTX64.EFI` откладывается в сторону, чтобы ВМ не загрузила сам работающий Linux.
После установки всё возвращается. systemd-boot найдёт Windows на общем ESP сам.

## Использование

Раздел `LOLSSD` (exFAT) монтируется сам при подключении SSD, утилита запускается прямо с него.
Без аргументов — меню: сверху итог проверки компьютера, ниже действия.

```
/run/media/$USER/LOLSSD/lolssd
```

На новой системе меню первым пунктом предлагает подготовить Linux для работы внутри Windows.
Те же действия есть командами, для скриптов:

```
/run/media/$USER/LOLSSD/lolssd check            # подходит ли компьютер, ничего не меняет
sudo /run/media/$USER/LOLSSD/lolssd boot        # один раз загрузиться в Windows на SSD
/run/media/$USER/LOLSSD/lolssd profile          # подготовить Linux внутри Windows (и после обновления ядра)
/run/media/$USER/LOLSSD/lolssd drivers ПУТЬ...  # драйверы для Windows: папки с .inf, установщики .exe/.msi
```

Драйверы ложатся в `LOLSSD/drivers`. Пакеты INF Windows ставит сама при следующей загрузке,
установщики `.exe` и `.msi` выкладывает в папку `Drivers` на рабочем столе — их запускаешь сам.

`boot` ставит одноразовый `BootNext` и перезагружает (`--no-reboot` — без перезагрузки,
`--cleanup` — удалить свою запись из NVRAM). Без утилиты — меню загрузки прошивки (F8/F12/Esc).

В Windows:
- **«Restart into Windows»** в «Пуске», в «Служебные — Windows», — перезагрузиться снова в эту Windows (обычная
  перезагрузка уводит в Linux).
- **«Linux»** (в «Пуске» и на рабочем столе) — твой Linux в ВМ, на весь экран каждого монитора.
  Нужен профиль (`lolssd profile`) и права администратора (UAC: ВМ открывает диск хоста).
  Ctrl+Alt+M → Exit viewer отдаёт монитор Windows (например, под игру), Ctrl+Alt+F12 на нём
  возвращает его Linux. Выключать — изнутри Linux (`poweroff`), не перезагрузкой Windows.
- **«Linux (QEMU windows)»** — то же, но экраны в окнах самого QEMU, а не в TigerVNC: проба,
  что плавнее. Окна сворачиваются как обычные; Ctrl+Alt+G отпускает клавиатуру (иначе Win и
  Alt+Tab уходят в Linux).
- **«Linux terminal»** — тот же Linux, но только консоль, без рабочего стола; ВМ одна на оба
  ярлыка: если она уже работает, ярлык подключается к ней.

После обновления ядра на хосте профиль снимают заново: образ загрузки ВМ содержит ядро.

## Linux внутри Windows: что работает

- раскладка мониторов как в твоём Linux (Hyprland): Windows сама ставит экраны так же — что
  зеркалится, что расширяет рабочий стол и в каком порядке; монитор узнаётся по EDID, а не по
  порту. После перестановки мониторов в Linux — «Обновить подготовку» в меню `lolssd`;
- твоя система целиком: ядро, модули DKMS (VPN и т. п.), systemd, сервисы, `/home`;
- несколько мониторов, курсор ведёт Windows;
- клавиатура через твой keyd, включая Super и Copilot/Menu как правую Super;
- звук — на тех же устройствах PipeWire, что на железе;
- сеть через NAT Windows; работает и zapret.

Чего нет: видеокарты в ВМ (рисует процессор, YouTube в высоком разрешении тянет плохо),
больше ~30 кадров в секунду, программ на hyprtoolkit (hyprpaper при смене обоев). Подробно —
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), §6–7.
