# lolssd

League of Legends на внешнем SSD для любого компьютера с Linux.

Внешний SSD с урезанной Windows и лолкой: подключил, загрузился с него, играешь. По желанию твой
Linux продолжает работать внутри этой Windows — та же установка с внутреннего диска, твой
композитор на весь экран, отдельно на каждом мониторе.

Заранее в Linux ничего ставить не нужно: всё, что требуется от системы, делает утилита
`lolssd`, лежащая на самом SSD.

> **Проверено только на железе автора.** На другом может не заработать, ничего не обещаю.

## Статус

Проектирование и первый прототип. Архитектура: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), прогон прототипа: [docs/PROTOTYPE.md](docs/PROTOTYPE.md).

## Почему так

Vanguard (античит Riot) работает на уровне ядра Windows и не запускается ни через Wine/Proton,
ни в виртуальной машине, ни в облачном гейминге. Остаётся настоящая Windows на настоящем
железе. Этот проект делает её отдельным внешним диском, который не трогает систему хоста.

## Сборка

```
make dist   # все бинарники и скрипты в dist/, разложенные так, как они ложатся на SSD
make wsl    # пусковой WSL-дистрибутив (Debian stable) и MSI WSL: без Docker и без root
make iso ISO=Windows.iso [DRIVERS=папка с INF]   # установочный ISO со всем внутри
make test
```

Все бинарники статические, без зависимостей.

### Утилита для Linux (`dist/LOLSSD/host/lolssd`)

Лежит на разделе `LOLSSD` и запускается на любом Linux.

Запуск с раздела: `sh /run/media/$USER/LOLSSD/lolssd.sh <команда>` (udisks монтирует FAT без права запуска файлов, скрипт запускает копию из `/tmp`).

- `lolssd check` — подходит ли компьютер: UEFI, Secure Boot, TPM 2.0, виртуализация, IOMMU,
  память, а при запуске с SSD ещё скорость USB-порта и работает ли UASP. Ничего не меняет.
- `lolssd profile` — описать систему для режима «Linux внутри Windows» и сохранить описание
  на SSD (`profiles/<machine-id>.json`): что монтировать (включая LUKS, LVM, подтомы btrfs),
  пользователя, мониторы с EDID. Запускается без sudo, ничего не меняет.
- `sudo lolssd boot` — перезагрузиться в Windows на SSD один раз. Порядок загрузки хоста не
  меняется: следующая загрузка после Windows снова идёт в Linux. `--no-reboot` только
  готовит загрузку, `--cleanup` удаляет созданную запись из NVRAM.

### Windows-часть (`dist/windows/`)

`lolssd-win.exe` кладётся в образ в `C:\Program Files\lolssd\`. Настройка Windows при установке: [build/setup](build/setup/README.md).

- `lolssd-win nvram-guard` — при каждом старте Windows (задание планировщика от SYSTEM) убирает
  из `BootOrder` хоста записи, ведущие на ESP этого SSD, а созданные самой Windows удаляет.
  Чужие записи и их порядок не трогает. Журнал: `C:\ProgramData\lolssd\lolssd-win.log`.
- `lolssd-win mount` — при входе в Windows: если на SSD есть профиль этого компьютера
  (`lolssd profile`), подключает диски хоста в WSL для режима «Linux внутри Windows».
  Нет профиля — ничего не делает.
- `lolssd-win restart` — ярлык «Restart into Windows (SSD)» в «Пуске»: перезагрузка сразу снова в
  эту Windows (BootNext на ESP SSD; обычная перезагрузка уводит в систему хоста). Права
  администратора — через запрос UAC.
- `lolssd-win desktop` — ярлык «Linux desktop (host)»: Hyprland хоста в WSL и полноэкранный
  TigerVNC на каждом мониторе. **Ctrl+Alt+F12** (или Ctrl+Alt+M → Exit viewer) отдаёт монитор под
  курсором Windows (например, под игру), Ctrl+Alt+F12 возвращает его Linux.

### Пусковой WSL-дистрибутив (`dist/wsl/lolssd.tar`)

Debian stable (сейчас trixie): это «прибор» для `systemd-nspawn`, `cryptsetup`, `lvm2`, `xkbcli` и `wayvnc`,
который не должен протухать, как rolling release. Собирается `build/wsl.sh` из официального
корневого архива Debian (того, из которого делают их Docker-образы), пакеты ставит его же `apt`
внутри `unshare --map-auto` — без Docker и root, на любом Linux. Внутри `lolssd-wsl` в
`/usr/local/bin/` и `wsl.conf` (systemd, root по умолчанию, `/mnt/c`). В образ попадает через
`make iso`, импортируется при первом входе. Ярлык «Linux terminal (SSD)» открывает именно его.
Команды (от root):
- `lolssd-wsl up` — поднять систему хоста по активному профилю. Сначала проверяет, что хост
  выключился чисто: не в гибернации, без незавершённого журнала ext4. Иначе отказ.
- `lolssd-wsl run -- команда` — запустить программу хоста от вашего пользователя, с графикой
  через WSLg и ускорением через GPU-PV. Обновления ядра изнутри Windows заблокированы.
- `lolssd-wsl session` — рабочий стол хоста: Hyprland вложенным, по выходу на каждый монитор
  Windows, с вашим конфигом. Правила, привязанные к мониторам (по порту или `desc:`), переводятся
  на вложенные выходы обёрткой, сам конфиг не меняется.
- `lolssd-wsl down` — опустить всё обратно.
